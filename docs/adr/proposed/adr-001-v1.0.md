# ADR-001: Constrain Edge Invalidation with a Typed Ontology and Reference-Time Discipline

**Status:** Proposed
**Date:** 2026-08-25
**Context:** A hygiene audit of the Docker Neo4j graph found that 56% of all facts are marked invalid, and that 85% of those were never superseded by anything. The cause is not "the temporal feature working"; it is a specific code path in `graphiti_core` that expires an incoming edge at write time based on the `valid_at` of a semantically-similar edge elsewhere in the namespace. `biosciences-memory` already carries most of the mitigation; `graphiti-fastmcp` does not.

**Extends:** [`docs/plans/2026-02-27-graphiti-fastmcp-migration-design.md`](../../plans/2026-02-27-graphiti-fastmcp-migration-design.md) — which specified the entity types, edge types, and `edge_type_map` this ADR now argues are load-bearing for correctness, not just for domain modelling.

---

## 1. Context and Problem Statement

### Measured state

Docker Neo4j, measured 2026-08-24: 7,182 entities, 504 episodes, 83 namespaces, 11,054 `RELATES_TO` facts.

| Signal | Value | Reading |
|---|---|---|
| Facts marked invalid | 6,183 / 11,054 (56%) | — |
| Invalidated edges that are the **only** edge between their node pair | **5,244 / 6,183 (85%)** | Nothing superseded them |
| Edges expiring within 10 minutes of creation | 3,652 / 6,164 (59%) | Not temporal change |
| Edges surviving beyond 24 hours | 750 (12%) | The only bucket consistent with real-world change |
| Edges with `invalid_at` **earlier than** `created_at` | 526 | Structurally impossible as a fact lifetime |

Genuine supersession leaves a live replacement behind. These have none.

The rate tracks episode count rather than subject matter, which is the signature of a mechanical cause:

| Namespace | Episodes | Invalidated |
|---|---|---|
| `aie9_curriculum_sessions_2026` | 2 | **0%** |
| `aie9-session-18` | 3 | 53% |
| `ai_makerspace_bootcamp_2026` | 21 | **82%** |
| `xmas-rpg-planning` | 47 | 73% |
| `open-biosciences-migration-2026` | 66 | 66% |

Sampled casualties from `xmas-rpg-planning`, all expired 125–128 seconds after creation inside a single ingestion run:

> "The DM Agent coordinates and orchestrates actions for Character Agent Zeek during combat"
> "ADR-005 specifies that the game_world/ directory holds state for the current (single) combat only"

Permanently-true architectural statements, uncontradicted, dead in two minutes.

### Root cause in `graphiti_core`

Two facts from `graphiti_core/utils/maintenance/edge_operations.py` together explain every number above.

**(a) Invalidation candidates are LLM-selected, not structural.** `invalidation_candidates` is built from `contradicted_facts` indices the LLM returns over a semantically-retrieved set of `existing_edges`. Nothing requires a candidate to share a node pair with the new edge.

**(b) An incoming edge can be expired at creation.** Before contradiction resolution runs:

```python
if resolved_edge.expired_at is None:
    invalidation_candidates.sort(key=lambda c: (c.valid_at is None, ensure_utc(c.valid_at)))
    for candidate in invalidation_candidates:
        if candidate_valid_at_utc > resolved_edge_valid_at_utc:
            resolved_edge.invalid_at = candidate.valid_at   # copied from ANOTHER edge
            resolved_edge.expired_at = now                  # at write time
            break
```

If any candidate carries a later `valid_at`, the **new** edge is written already dead.

This accounts for each observation exactly:

- **85% sole-edge** — the edge was born invalid, so no sibling was ever created between that pair.
- **59% within 10 minutes** — `expired_at = now`, at write time.
- **526 with `invalid_at` before `created_at`** — `invalid_at` is copied from a *different* edge's `valid_at`, which may predate the new edge entirely.

So the defect is not over-eager contradiction detection in the abstract. It is **`valid_at` ordering deciding which edge survives, over a candidate set chosen by semantic similarity.** Two facts that merely sound alike can kill each other.

### Secondary consequence: entity fragmentation

Where only the generic entity types are loaded (`Requirement`, `Preference`, `Procedure`), extraction promotes JSON field *values* to entities. `don_branson_job_search` contains nodes literally named `resume` (a `Document` whose entire summary is one file path), `ready_to_submit`, and `logistics (availability, compensation expectations, must-have fit)`. A node named `resume` can never accumulate meaning — every resume in every application collapses into it.

Across the graph this shows as **489 entity names appearing in more than one namespace, 812 redundant nodes, 11% of all entities.** `TP53` exists as 15 unconnected nodes; `ACVR1` as 11. Since entity resolution and edge invalidation both operate strictly *within* a namespace, cross-namespace synthesis is structurally impossible.

## 2. Decision

Adopt a **typed ontology plus reference-time discipline** as the primary control on invalidation, and treat forking `graphiti_core` as a last resort gated on measurement.

Three levers, in leverage order.

### Lever 1 — Load a constrained ontology everywhere (required)

`biosciences-memory` already defines this. `graphiti-fastmcp` does not, and is the graph where the 56% was measured.

`src/biosciences_memory/models/entity_types.py:348`:

```python
EDGE_TYPE_MAP: dict[tuple[str, str], list[str]] = {
    ("Gene", "Protein"):   ["AssociatedWith"],
    ("Drug", "Gene"):      ["TargetOf"],
    ("Drug", "Disease"):   ["TreatedBy"],
    ("Protein", "Protein"):["InteractsWith"],
    ("Entity", "Entity"):  ["AssociatedWith"],   # fallback
}
```

Wired at `src/biosciences_memory/server.py:198-214` via `custom_edge_types` / `custom_edge_type_map`.

Constraining legal edge types per node-type pair shrinks the candidate set the LLM judges contradictions over, which is the input to both failure paths above. Custom entity types independently fix the junk-node problem by giving extraction real types to assign.

This is the mechanism Zep documents as *Custom Entity and Edge Types*; the managed equivalent is the `set-ontology` API.

### Lever 2 — Reference-time discipline on batch ingestion (required)

The premature-expiry path triggers on `valid_at` ordering, and `valid_at` derives from episode `reference_time` when the LLM does not extract an explicit date.

**Standard:** episodes ingested as one batch describing one point in time MUST share a single `reference_time`. Sequential wall-clock stamps across a batch create an artificial ordering in which each episode's edges outrank the previous episode's, which is the most plausible driver of the 0% → 82% gradient.

### Lever 3 — Fork-level gate (deferred, measurement-gated)

`open-biosciences/graphiti` is a fork, so the `expired_at is None` block can be gated directly — for example, requiring a candidate to share a node pair before it may expire an incoming edge.

**This is deferred.** It diverges from upstream and must not be attempted before Levers 1 and 2 are measured. Adopt only if the A/B below shows the ontology fails to bring the rate under target.

---

## 3. Implementation Standard

Any Graphiti-backed service in this program MUST:

1. Load custom entity types **and** an `edge_type_map` at client construction. Generic-types-only is a defect, not a default.
2. Include an `("Entity", "Entity")` fallback so untyped pairs remain expressible.
3. Pass an explicit `reference_time` per episode, shared across a batch representing one moment.
4. Emit extraction detail at `DEBUG` — `GRAPHITI_LOG_LEVEL=DEBUG`. The `Extracted new nodes` / `Extracted new edges` lines are `logger.debug`, so `INFO` shows nothing about what an episode actually produced.

---

## 4. Validation

The decision is not accepted until measured. Levers 1 and 2 are validated together:

1. Select one source corpus of ≥20 episodes (`ai_makerspace_bootcamp_2026` is the sharpest case at 82%).
2. Ingest identically into two scratch namespaces: `scratch_ontology_control` (generic types, sequential reference times) and `scratch_ontology_test` (full `EDGE_TYPE_MAP` + custom types, shared batch reference time).
3. Compare, per namespace:
   - `expired_at IS NOT NULL` as a share of all `RELATES_TO`
   - share of invalidated edges that are the sole edge between their pair
   - distribution of `duration.between(created_at, expired_at)`
   - count of entity names appearing in more than one namespace

**Target:** invalidation below 30%, and sole-edge invalidation below 20% of invalidated edges. Anything above that leaves Lever 3 on the table.

Remediation of existing data is **sequenced after** this fix. `group_id` cannot be renamed in place, so consolidation means export → re-ingest → delete; re-ingesting into larger namespaces while the rate still scales with episode count would multiply the damage.

---

## 5. Consequences

**Positive.** Fewer facts destroyed at write time. Retrieval improves because default search excludes invalidated edges — 5,244 facts (47% of the graph) are currently invisible while still carrying embedding and index cost. Typed entities make cross-namespace consolidation meaningful rather than merging junk.

**Negative.** An `edge_type_map` is a schema, and schemas need maintenance; too tight a map suppresses legitimate relationships. The `("Entity", "Entity")` fallback is the pressure valve. Domain ontologies do not transfer between namespaces — the biosciences map is wrong for career or curriculum data, so each domain needs its own.

**Neutral.** Existing invalidated edges are not repaired by this decision. It stops the bleeding; remediation is separate work.

**Risk if rejected.** The rate scales with episodes per namespace, so it worsens with use. Every namespace that grows past ~20 episodes trends toward 80% invalidation.

---

## 6. Alternatives Considered

**Disable invalidation entirely.** Rejected — it discards the temporal modelling that motivates Graphiti, and genuine supersession does occur (the 12% surviving beyond 24 hours).

**Tune extraction prompts only.** Rejected as insufficient — path (b) is deterministic code, not a prompt, and executes regardless of what the extractor concludes.

**Fork first.** Rejected as premature. It is the highest-cost, highest-divergence option and would be attempted without evidence the supported configuration is inadequate.

**Accept it as normal churn.** Rejected on evidence — 85% sole-edge and 526 edges invalid before creation are not consistent with knowledge change under any reading.
